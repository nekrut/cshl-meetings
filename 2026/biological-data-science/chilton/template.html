AWhat it does

The Galaxy Workflow Foundry helps coding agents turn a paper or a Nextflow pipeline into a native, tested Galaxy workflow.

Getting a workflow right is a knowledge problem, not a syntax problem: Galaxy’s tools, collections, and idioms change faster than model training data. So the Foundry keeps that knowledge in a wiki people can read and review [3], compiles it into agent skills, and lets programs, not the model, decide when a workflow is right. What it can’t resolve, it writes down.

Native: Galaxy’s own Tool Shed tools, pinned to exact revisions, on Galaxy collections.

BHow it works

A route is a chain of Molds, each cast into a skill. A planning lane turns a paper or a Nextflow pipeline into a workflow brief. Once a person has reviewed it, one shared spine of {{SPINE_LEN}} phases builds, checks, and tests the Galaxy workflow. Filled stations are gates: a program, not the model, signs each one.

CInside the loop

Pinned, not named.

Phase {{LOOP_PHASE}} builds the workflow one step at a time. Each pass, gxwf draft-next-step picks the next unfinished step; the discover-shed-tool skill (Fig. 1) searches the Tool Shed and pins one wrapper to an exact changeset; the agent fills in the step; gxwf draft-validate checks it against that tool’s schema. The DengueSeq run took {{LOOP_ITERATIONS}} passes.

Gaps are written down.

The run’s ledger closed {{LEDGER_RESOLVED}} of {{LEDGER_ENTRIES}} requirements and left {{LEDGER_OPEN}} open, each stated in words for the reviewer: for example, that the source’s filtered variant table is not reproduced, a cut the reviewed brief chose.

DChecked, then run

Typed, not guessed.

In phase {{VALIDATE_PHASE}}, gxwf validate checks every parameter and every connection, collection map-over included, against the tools’ real schemas. No job is queued, so an agent can repair in a tight loop.

{{RECEIPT_VALIDATED}}
The last check is a real run.

gxwf checks the structure. Then Planemo installs the pinned tools in a real Galaxy and runs the workflow’s test. That run is the validation: real jobs, real outputs, checked against the expected ones.

ERails, not reminders

The companion Orbit study ran agents on public Galaxy [1]. Its lesson: skills are guidance, not enforcement [1]. What held were the rails. A connection check caught an agent’s bad tximport wiring before anything ran, and Orbit’s evidence gate now refuses by default [1].

The Foundry is built the same way: the model drafts and repairs; gxwf and Planemo decide. Its compilation pipeline is described in [1]; here we show its knowledge base, provenance, and checks.

[1] also reports a 60-step workflow the Foundry compiled from an RNA-seq paper’s methods text; comparing with the authors’ data found a model choice the methods left out.
